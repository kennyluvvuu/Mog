# mog — фронтенд

Веб-приложение для ИИ-оценки внешности по шкале луксмаксинга. Загружаете фото — получаете балл от 1 до 10, тир (от `sub3` до `true adam`), разбор шести метрик лица и список практических рекомендаций.

## Что умеет приложение

- **Лендинг** с описанием сервиса, шкалы тиров, метрик и режимов разбора
- **Регистрация и вход** по email и паролю
- **Загрузка фото** перетаскиванием, через выбор файла или съёмкой с веб-камеры прямо в браузере
- **Три режима разбора**: мягкий, честный и жёсткий — меняется тон текста, но не сам балл
- **Живой прогресс обработки** в реальном времени, с автоматическим переключением на опрос, если стрим закрылся
- **Страница результата**: круговой индикатор балла, бейдж тира, метрики с полосами, текстовый разбор и советы
- **История оценок** со сводной статистикой: всего оценок, лучший и средний балл, лучший тир
- **Профиль** с редактированием никнейма
- **Информационные страницы**: как это работает, шкала тиров, FAQ, о проекте, приватность

## Требования

- Node.js 20 или новее
- Запущенный локальный бэкенд Supabase (см. README в корне репозитория)

## Запуск

1. Установите зависимости:

   ```bash
   npm install
   ```

2. Создайте файл настроек из примера:

   ```bash
   cp .env.example .env.local
   ```

3. Запустите бэкенд из корня репозитория и скопируйте оттуда ключ доступа:

   ```bash
   cd .. && bun run supabase:start
   ```

   В выводе команды найдите строку `Publishable key` (значение вида `sb_publishable_...`) и вставьте его в `.env.local` в переменную `NEXT_PUBLIC_SUPABASE_ANON_KEY`.

4. Запустите приложение:

   ```bash
   npm run dev
   ```

   Откройте [http://localhost:3000](http://localhost:3000).

## Переменные окружения

| Переменная | Описание |
| :--- | :--- |
| `NEXT_PUBLIC_SUPABASE_URL` | Адрес шлюза Supabase. Для локальной разработки — `http://127.0.0.1:54321` |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Публичный ключ доступа из вывода `supabase start` |

## Что нужно знать перед первым запуском

**Нужен запущенный воркер.** Оценки обрабатывает фоновый воркер, которому требуется ключ Groq API. Без него загруженное фото так и останется в статусе «В очереди».

**Фото в истории видно не всегда.** Хранилище закрыто политиками доступа, и подписать ссылку на файл может только сервер — в момент, когда оценка завершается. Приложение запоминает такую ссылку примерно на час, поэтому фото видно у оценок, завершившихся при открытой странице. У более старых записей вместо снимка показывается заглушка «Фото недоступно» — это ограничение бэкенда, а не ошибка интерфейса.

**Камера работает только по HTTPS.** Браузеры дают доступ к камере лишь на защищённых страницах. Локально `http://localhost` тоже считается безопасным, поэтому в разработке съёмка работает, а вот при открытии сайта по IP-адресу без HTTPS кнопка съёмки сообщит об ошибке.

**Режим разбора хранится в браузере.** Бэкенд передаёт выбранный режим в обработку, но не сохраняет его в базе, поэтому приложение запоминает режим локально. При очистке данных браузера или входе с другого устройства подпись режима у старых оценок пропадёт.

## Структура проекта

```text
app/                  Маршруты и страницы приложения
  (auth)/             Вход и регистрация
  rate/               Создание новой оценки
  ratings/[id]/       Просмотр результата
  dashboard/          История оценок
  profile/            Настройки профиля
components/
  ui/                 Базовые компоненты интерфейса (shadcn)
  layout/             Хедер, подвал, навигация
  landing/            Секции главной страницы
  rating/             Загрузка фото, прогресс, результат, история
  auth/               Формы входа, регистрации и профиля
  motion/             Обёртки анимаций появления
  providers/          Провайдеры запросов и авторизации
lib/
  api/                Работа с бэкендом
  hooks/              Хуки запросов и живого статуса
  schemas/            Схемы и типы данных
  constants/          Справочники тиров, режимов и вопросов
```
